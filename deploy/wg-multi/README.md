# Несколько WireGuard-тоннелей без конфликта (+ атака через все)

## Зачем

Все конфиги A&D маршрутят одни и те же игровые подсети (`10.60.0.0/16`,
`10.10.10.10`). Если бросить их все в **главную** таблицу маршрутов — выигрывает
один, остальные мертвы, да ещё и основной VPN сервера может лечь. Нужно policy-routing.

## Как устроено (Linux, сервер)

Для каждого `*.conf` из `/etc/ad-ctf/wg/` скрипт `wg-multi.sh`:

1. делает копию конфига с `Table = 10<i>` в `[Interface]` — поэтому `wg-quick`
   кладёт маршруты тоннеля в **отдельную** таблицу, а главную (основной VPN) не трогает;
2. поднимает интерфейс `adc<i>` (`wg-quick up`);
3. добавляет `ip rule add fwmark <M> lookup 10<i>` — трафик с меткой `M` уходит
   этим тоннелем. Приоритет правил выше `main`, поэтому помеченный трафик идёт в
   свой тоннель, а непомеченный — как раньше (основной VPN);
4. пишет `/etc/ad-ctf/vpn.env` → `FARM_VPN_MARKS=<M1,M2,...>`.

Ферма (`farm/vpn_balance.py`, включается при наличии `FARM_VPN_MARKS`) метит
исходящие сокеты `SO_MARK` по кругу — **каждая атака уходит другим тоннелем**.
Эксплойты не меняются: они просто пользуются `socket`/`requests`.

```
   farm worker --SO_MARK=M1--> ip rule fwmark M1 -> table 101 -> adc1 -> тоннель 1
   farm worker --SO_MARK=M2--> ip rule fwmark M2 -> table 102 -> adc2 -> тоннель 2
   (непомеченное)           -> main table        -> основной игровой VPN
```

Карта `конфиг → iface → table → fwmark`: `wg-multi.sh status`.
`SO_MARK` требует CAP_NET_ADMIN — на боксе команды ферма работает от root, так что
просто работает; иначе балансировка молча отключается и всё идёт одним маршрутом.

## Команды

```bash
sudo ./wg-multi.sh up        # поднять все, записать FARM_VPN_MARKS
sudo ./wg-multi.sh test      # curl --interface по каждому тоннелю к 10.10.10.10
sudo ./wg-multi.sh status    # тоннели, ip rule, маршруты по таблицам, карта
sudo ./wg-multi.sh down      # опустить все, убрать правила
./wg-multi.sh marks          # напечатать строку FARM_VPN_MARKS
```

## На этом ПК (Windows)

В Windows нет fwmark-роутинга, поэтому одновременный балансинг по тоннелям —
функция **сервера**. На ПК (`../windows/wg-multi.ps1`) тоннели ставятся службами и
переключаются вручную: удобно как запасной путь/вторая идентичность и для доступа
к дашборду. Основной боевой хост — сервер.
