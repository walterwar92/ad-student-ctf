## Суть (в двух словах)

`POST /api/coupons` подписывает HMAC-«пропуск» (permit) на **любой** `object_id`, который
пришёл от клиента, **не проверяя, что этот объект принадлежит вызывающему**. А
`POST /api/memories/<mid>/read` принимает такой пропуск, сверяет HMAC и расшифровывает
содержимое памяти `mid`. Чекер кладёт флаг в «память». Значит:

> любой зарегистрированный игрок подписывает пропуск на `object_id = <mid чужой памяти>` и
> читает чужой флаг. Это **confused deputy / BOLA (object-level authz)** — сервер выступает
> «запутанным замом» и выдаёт мандат на чужой ресурс.

flag_id (публичный, из attack_data) для muha — почти наверняка и есть `mid` памяти с флагом,
т.е. атакующему даже угадывать ничего не надо.

## Цепочка атаки (для понимания, НЕ для фермы — это раздел защиты)

```
register/login                               # получили свою сессию
POST /api/flies    {name, profession}        # эксплойт сперва заводит «муху» (fly_id)
POST /api/coupons  {fly_id, object_id: MID}  # MID = чужая память (= flag_id цели); сервер вернул token
POST /api/memories/MID/read {token}          # HMAC валиден → сервер расшифровал и отдал чужой флаг
```

> Имена полей взяты из `farm/sploits/muha.py` (`object_id`, `token`, `fly_id`). В шаблонах
> ниже «permit» = реальный `token`; сверь с `app.py` на боксе.

Корень: **авторизация на доступ к объекту не проверяется ни при выдаче пропуска, ни при
погашении.** HMAC лишь подтверждает «сервер это подписал», а не «тебе можно».

## Патч (главный, SLA-безопасный): проверка владения ПРИ ВЫДАЧЕ пропуска

Чини в `POST /api/coupons`: прежде чем подписать permit на `object_id`, убедись, что текущий
аутентифицированный пользователь **владеет** этим объектом (или он в его share-листе). Не
владеет → `403`, ничего не подписываем.

Почему именно при выдаче, а не только при чтении — см. «SLA-ловушку» ниже: легальный флоу
«поделиться памятью» это владелец, который чеканит пропуск на **свою** память; атака отличается
тем, что просит пропуск на **чужую**. Проверка владения на выдаче рубит атаку и **не трогает**
легальный шэринг.

Шаблон (Flask; подставь реальные имена — `current_user`, модель памяти, поле владельца):

```python
@app.post("/api/coupons")
def issue_coupon():
    user = require_auth()                      # как в сервисе: сессия/токен → текущий юзер
    object_id = request.json["object_id"]

    mem = Memory.query.get(object_id)          # найди объект (память), на который просят пропуск
    if mem is None:
        abort(404)
    # ГЛАВНАЯ СТРОКА: пропуск выдаём только владельцу (или тому, кому владелец его расшарил)
    if mem.owner_id != user.id and user.id not in getattr(mem, "shared_with", ()):
        abort(403)                             # не твой объект — пропуск не подписываем

    # дальше — как было, подпись permit; желательно привязать к юзеру и сроку (см. ниже)
    return {"permit": sign_permit(object_id, user.id)}
```

## Усиление (defense-in-depth, по возможности)

1. **Привяжи пропуск к субъекту и сроку.** Подписывай не только `object_id`, а
   `f"{object_id}|{user.id}|{exp}"`, и при погашении пересчитывай HMAC с **текущим**
   пользователем и проверяй `exp`. Тогда пропуск, выданный одному, нельзя переиграть другим,
   и его нельзя «дотюнить».

   ```python
   def sign_permit(object_id, uid, ttl=120):
       exp = int(time.time()) + ttl
       msg = f"{object_id}|{uid}|{exp}".encode()
       mac = hmac.new(PERMIT_SECRET, msg, hashlib.sha256).hexdigest()
       return f"{object_id}.{uid}.{exp}.{mac}"

   def verify_permit(token, object_id, uid):
       try:
           oid, tuid, exp, mac = token.split(".")
       except ValueError:
           return False
       if oid != str(object_id) or tuid != str(uid):   # пропуск именно этого юзера на этот объект
           return False
       if int(exp) < time.time():
           return False
       good = hmac.new(PERMIT_SECRET, f"{oid}.{tuid}.{exp}".encode().replace(b".", b"|"),
                       hashlib.sha256).hexdigest()
       return hmac.compare_digest(mac, good)            # всегда constant-time сравнение
   ```

2. **Проверка владения ПРИ ЧТЕНИИ** (`/api/memories/<mid>/read`) — только если чекер читает
   флаг **тем же** владельцем (см. ниже). Иначе сломает SLA. Если привязал пропуск к юзеру (п.1),
   то строгая owner-only проверка на чтении уже избыточна для блокировки атаки.

## ⚠️ SLA-ловушка — проверь, ЧТО делает чекер, прежде чем трогать путь чтения

Правило A&D: закрыть дыру, **не уронив то, что проверяет чекер** (иначе минус defense-очки).
Критичный вопрос: чекер в своём `get` читает флаг **тем же** юзером, что положил, или **другим**
через пропуск (проверяя фичу шэринга)?

- **(S1) тем же владельцем** → безопасна и проверка на выдаче, и owner-only на чтении.
- **(S2) другим юзером по пропуску** → owner-only **на чтении** сломает чекер (его легальный
  `get` — не владелец). А вот **проверка владения на выдаче** безопасна и здесь: пропуск чеканит
  владелец на свою память, затем передаёт — выдача проходит; атакующий просит пропуск на чужое —
  выдача рубится.

Вывод: **проверка владения на ВЫДАЧЕ безопасна в обоих случаях** — это и есть главный патч.
Строгую owner-проверку на чтении добавляй, только если убедился, что это S1.

Как проверить на боксе (прочитать чекер muha — это НЕ сервис, его можно читать):

```bash
# на боксе найди чекер muha и посмотри его get(): создаёт ли он нового юзера / логинится ли
# под другим перед чтением флага
find /opt/services/muha / -iname '*checker*' 2>/dev/null
grep -nEi 'def (get|put|check)|register|login|coupon|permit|/read|object_id' <путь_к_чекеру>
```

Если `get` не регистрирует нового юзера и читает под тем, кто клал → S1 (можно и owner-only на
чтении). Если регистрирует/логинится другим и использует пропуск → S2 (только проверка на выдаче).

## Почему filter_proxy здесь плохо помогает

`defense/filter_proxy.py` режет по **байтовой сигнатуре** payload'а. Здесь атака и легальный
запрос отличаются только **значением** `object_id` (свой mid против чужого) — по байтам их не
разделить. Сетевой фильтр эту IDOR чисто не закроет.

Единственный сетевой времянка-вариант (рискованный): резать `/api/coupons` целиком, **если**
чекер им не пользуется (это как раз и выясняет grep выше). Если пользуется — упадёт SLA. Поэтому
здесь **обязателен код-патч**, а не прокси.

# Вектор 2 — CBC padding-oracle через IDOR-утечку капсулы

Это **fallback** в эксплойте (`_padding_oracle`, `farm/sploits/muha.py:165`): работает, даже
когда coupon-IDOR уже закрыт. Состоит из двух багов, которые срабатывают только в паре:

- **2a. IDOR на капсуле.** `GET /api/memories/<mid>/capsule` отдаёт `archive` **любой** памяти
  без проверки владения. `archive` = `base64(IV ‖ AES-CBC-ciphertext)` JSON-а
  `{"owner","title","content"}` под одним общим `archive_key`. Контент (= флаг) в хвосте.
- **2b. Padding-oracle на preview.** `POST /api/archives/preview {archive}` возвращает **422**
  при битом PKCS7-паддинге и **другой** статус иначе. Классический оракул: по статусу
  атакующий побайтно восстанавливает plaintext **без ключа** и без всяких прав.

## Цепочка атаки (для понимания)

```
register                                   # любая своя сессия
GET  /api/memories/MID/capsule             # 2a: утекла чужая капсула IV‖ct (MID = flag_id цели)
POST /api/archives/preview {archive:...}   # 2b: 422/не-422 по каждому форжу → оракул
   … ~256 запросов на байт, ферма крутит пул сокетов и вытаскивает content=флаг за ~15-20с
```

Корень: (2a) нет object-level authz на выдаче капсулы; (2b) ответ `/preview` **различим по
валидности паддинга** — утечка через сторонний канал (статус-код).

## Патч вектора 2 (бери оба пункта — они перекрывают друг друга)

### Главный: owner-only на капсуле (убивает оракул в корне)

Нет ключа на чужую капсулу — нечего скармливать оракулу. Чини в `GET /.../capsule` так же,
как coupon: отдаём `archive` только владельцу (или кому расшарено).

```python
@app.get("/api/memories/<mid>/capsule")
def capsule(mid):
    user = require_auth()
    mem = Memory.query.get(mid)
    if mem is None:
        abort(404)
    if mem.owner_id != user.id and user.id not in getattr(mem, "shared_with", ()):
        abort(403)                             # чужую капсулу не отдаём
    return {"archive": mem.archive}            # дальше как было
```

### Defense-in-depth: убрать различимость ответа у preview

Даже если капсулу где-то ещё можно получить, оракул умирает, когда `/preview` отвечает
**одинаково** на «битый паддинг» и «валидный паддинг, но мусор внутри». Эксплойт решает
«паддинг ок?» по `!= 422` (`_oracle_valid`, строка 116) — сделай все ошибки неразличимыми:

```python
@app.post("/api/archives/preview")
def preview():
    raw = _unb64(request.json["archive"])
    try:
        pt = aes_cbc_decrypt(ARCHIVE_KEY, raw)     # unpad PKCS7 внутри
        data = json.loads(pt)                      # и парс — тоже внутри try
    except Exception:
        abort(422)                                 # ОДИН статус на ЛЮБУЮ ошибку: pad И json И т.п.
    return {"title": data.get("title"), "owner": data.get("owner")}  # как раньше, без content
```

Ключевое: `unpad` и `json.loads` — под **одним** `except`, и наружу идёт **один и тот же**
статус/тело. Тогда «валидный паддинг» больше не отличить от «битого» → оракул не
дискриминирует (его же проверка `len(hits)==0 or >6` на первом байте сама отвалится, строка 144).
Ещё надёжнее — encrypt-then-MAC: проверять HMAC над `archive` **до** расшифровки и реджектить
тем же 422; но это меняет формат капсулы — трогай, только если чекер не присылает в preview
произвольные архивы (см. SLA-ловушку).

## ⚠️ SLA-ловушка вектора 2 — что делает чекер с capsule / preview?

Та же логика, что и для вектора 1 — сперва прочитай чекер muha (его читать можно, это не сервис):

```bash
grep -nEi 'capsule|preview|archive|/memories/.*/(capsule|read)|422' <путь_к_чекеру_muha>
```

- **capsule:** если чекер забирает капсулу **только своей** памяти → owner-only безопасен.
  Если дёргает чужую (маловероятно) — сломает SLA, тогда опирайся на фикс preview.
- **preview:** если чекер зовёт preview на **валидном своём** архиве и ждёт `200` с
  `title/owner` — наш фикс это не трогает (успешный путь не изменился). Он лишь схлопывает
  **ветки ошибок** в один статус. Если же чекер специально ждёт именно `422` на заведомо
  битом паддинге как фичу — оставь `422` единым кодом ошибки (мы его и используем), но убедись,
  что «валидный-паддинг-но-мусор» даёт **тот же** `422`, а не `200/400`.

Правило прежнее: **owner-only на капсуле безопасен почти всегда** (легальный флоу читает свою
капсулу), и это главный патч вектора 2. Фикс preview — дешёвая страховка сверху.

## Почему filter_proxy и тут плохо помогает

`/preview`-запросы оракула байт-в-байт выглядят как легальный preview (меняется лишь
содержимое `archive`-блоба). Отрезать по сигнатуре нельзя; резать `/preview`/`/capsule`
целиком — только если чекер ими не пользуется (выясни grep-ом выше). Нужен код-патч.

# Латентный след (НЕ из эксплойта): `clone` копирует чужой `brain_key`

Найдено при чтении `app.py`, ферма это пока не использует. `POST /api/flies/<fid>/clone`
(обработчик `clone`) берёт `fly = get_fly(fid)` **без проверки владельца** и вставляет нового
«клона» с `g.user["id"]` в владельцах, но с **чужим `brain_key`** и выбранной `revision`
(0..counter). `brain_key` — это AES-GCM-ключ, которым шифруются воспоминания
(`store_memory`: `AESGCM(fly["brain_key"]).encrypt(nonce, content)`, где `nonce =
counter.to_bytes(12)`).

Почему **сейчас не крадёт флаг:** чтобы расшифровать чужое воспоминание, атакующему нужен его
`ciphertext+nonce`, а единственный эндпоинт, который их отдаёт (`/capsule`), теперь owner-locked.
Клон даёт ключ, но не даёт чужой шифротекст — цепочка не замыкается.

Почему это всё равно стоит починить (**defense-in-depth**): ключ детерминированного nonce +
общий `brain_key` — это заряженное ружьё. Если `/capsule` когда-нибудь регрессирует (или
появится другой путь утечки шифротекста), связка «клонировал чужую муху → получил `brain_key` →
nonce-reuse» сразу даёт восстановление чужого plaintext. Чекерный флоу клонирует **свою** муху,
поэтому owner-check безопасен по SLA.

```python
@app.post("/api/flies/<fid>/clone")
@authenticated
def clone(fid):
    ...
    fly = get_fly(fid)
    if fly is None:
        return fail("Муха не найдена", 404)
    if fly["owner"] != g.user["id"]:               # <-- добавить: клонировать только свою муху
        return fail("Это чужое сознание", 403)
    ...
```

> трогал; свериться с текущим кодом, не дублировать. Правка clone = пересборка образа → под
> SLA-гвоздь (см. ниже), делать только с подтверждения.
