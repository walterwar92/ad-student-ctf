================= КАК ПОЛЬЗОВАТЬСЯ =================
Это общий СТАРТОВЫЙ КОНТЕКСТ для новых чатов. Идея: 1 чат = 1 задача (эксплойт на сервис,
патч, разбор), и все чаты стартуют с одного и того же контекста, чтобы результаты стыковались.

Как применять в тест-день:
  1. Открой новый чат.
  2. Скопируй в него ВСЁ, что ниже строки "НАЧАЛО КОНТЕКСТА".
  3. В самом низу заполни блок "ЗАДАЧА ЭТОГО ЧАТА" под конкретную задачу.
     Для эксплойта можно вместо этого вставить заполненный farm/EXPLOIT_PROMPT_TEMPLATE.md.
  4. Повтори для каждого сервиса/задачи в отдельном чате (можно параллельно).

Эту шапку ("КАК ПОЛЬЗОВАТЬСЯ") копировать не нужно — она для тебя.

================= НАЧАЛО КОНТЕКСТА (копировать отсюда) =================

# Кто я и что делаю
Я готовлюсь к финалу Студент CTF в формате Attack & Defense (10 команд). Это легальная учебная
среда: официальная тестовая площадка организаторов, где атаковать сервисы соперников в игровой
сети разрешено правилами соревнования. Помоги с конкретной задачей, описанной в самом низу.

# Площадка и параметры игры (ForcAD)
- Платформа: ForcAD (github.com/pomo-mondreganto/ForcAD). VPN: WireGuard.
- Боксы команд: 10.60.N.2 (N=1..10). Игровой сервер / скорборд: http://10.10.10.10 (внутри VPN) или https://GAME_HOST (из интернета).
- Формат флага (регэксп): [A-Z0-9]{31}=
- Attack-data (публичные flag_id целей):
    GET http://10.10.10.10/api/client/attack_data
    -> {"service": {"team_ip": ["hint1","hint2", ...]}}      (hint == flag_id)
- Сдача флагов:
    PUT http://10.10.10.10/flags , заголовок  X-Team-Token: <мой_токен> , тело = JSON-массив.
    Пример: curl -s -H 'X-Team-Token: TOKEN' -X PUT -d '["FLAG1=","FLAG2="]' http://10.10.10.10/flags

# У меня есть своя "ферма" атак (отдельный проект). Эксплойты — её плагины.
Ферма сама берёт flag_id из attack-data, гоняет эксплойты по всем командам, сдаёт флаги
(с дедупом, ретраями и лимитами). ВАЖНО: любой эксплойт, который ты пишешь, должен ТОЧНО
соответствовать этому интерфейсу, чтобы встать в ферму без правок:

    def exploit(host: str, port: int, flag_id) -> list[str]:
        # вернуть список украденных флагов (строк); [] если ничего не нашли.
        # flag_id — публичный идентификатор жертвы из attack-data.
        # Может быть None — тогда дампь всё, что сможешь.

Жёсткие правила для эксплойта:
- только удалённый сетевой интерфейс сервиса (никаких серверных секретов и локальных файлов);
- ОБЯЗАТЕЛЬНО свои таймауты (socket.settimeout / requests timeout=5..7с) — ферма запускает
  эксплойты параллельно, зависший блокирует воркер;
- НЕ вызывай sys.exit и не давай исключениям улетать наружу при "ничего не нашли" — просто
  return [];
- возвращай чистые строки-флаги (ферма валидирует по регэкспу [A-Z0-9]{31}=); если возможно,
  дампь все флаги сервиса, а не только по одному flag_id;
- зависимости: лучше stdlib (socket / urllib) или requests. pwntools — только для pwn и только
  если ты уверен, что он установлен на атакующей машине; иначе сырые сокеты;
- файл должен запускаться и отдельно для проверки:
    python <name>.py <host> <port> <flag_id>   # печатает по флагу на строку.

# Что я жду в ответе (по умолчанию)
1) краткий анализ сервиса/задачи и уязвимости;
2) если это эксплойт — ОДИН готовый файл целиком строго под интерфейс выше, и по возможности
   проверка (запусти против указанного host:port или объясни логику и граничные случаи);
3) 2-3 строки: в чём именно дыра и как её патчить (мне это нужно и для защиты своего бокса).

# Подсказки по типу сервиса (используй по ситуации)
- web: SQLi/NoSQLi, IDOR (угадываемые id), обход авторизации, SSTI, path traversal, небезопасная
  десериализация, слабые/предсказуемые токены сессий.
- crypto: ECB / повтор гаммы (two-time pad), повтор nonce, предсказуемый seed/ключ,
  length-extension, слабый подписывающий секрет (брут), публично выставленный ciphertext,
  самодельные подписи (напр. WOTS без контрольной суммы / с переиспользованием ключа).
- pwn: переполнение буфера / формат-строка / off-by-one / логика; цель — заставить сервис
  отдать флаг (прочитать чужую запись/память). Обычно сырой сокет + заранее собранный payload.

# Разведка по прошлому году (баги часто повторяются или похожи)
Сервисы: workflow (2 уязвимости), zounds (2), secretscribble (3).
- secretscribble (сервис с /sign, /cabinet/<id>/, "Закрытая информация"): баг — подделка
  сессионной WOTS-куки (один глобальный ключ на все куки, без контрольной суммы). Эксплойт у
  меня УЖЕ готов и проверен — заново писать не нужно, если сервис тот же.
- zounds (защита): есть файловый "клинер", который может удалять флаги раньше, чем их заберёт
  чекер → падает SLA. Защита: замедлить/отключить клинер (но не дать файлам забить диск).
